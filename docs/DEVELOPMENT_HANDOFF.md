# 업무 관리 개발 인계 — 2026-11-25

## 흐름

스캔 업로드 → AI 초안 → 사용자 검토·확정 → DB 저장 → 매출 대조 → 사용자 최종 판정.
AI 추론 도구와 관리 서버의 존재만으로 이 전체 흐름의 자동 연동이 완료됐다고 간주하지 않는다.

## 확정된 업무 기준

- 하루 합계가 아니라 매출 건별로 계획과 비교한다. 오전/오후 별도 판정 가능.
- 실제 제공 구간의 시간을 합산한 다음 30분 단위 인정시간을 계산한다.
- 나머지 분 0~14 → 0분, 15~44 → 30분, 45~59 → 60분으로 인정한다.
- 계획과 실제 인정시간을 비교한다. 시작/종료 각각의 절댓값 차이만으로 판정하지 않는다.
- 휴게시간 위치만 달라지고 정해진 범위/총 제공시간 조건이 맞으면 문제없음으로 본다.
- 대상년월은 무시한다. 반납은 미실시로, 일괄결제는 제공기록지의 소급 체크를 확인한다.
- 비교 대상은 상단 숫자(시작/종료/제공시간/승인번호)이며 하단 서술 사유 판정은 사용자에게 맡긴다.
- 원본 엑셀 행을 보존한다. 자동 대조와 최종 사용자 판정을 분리한다.

## 현재 개발 구조

Python 개발 서버 + SQLite, schema migration/백업/복구, 사용자 관리,
문서 검토 및 초안 자동저장, 매출 import와 원본 행 보존, 테마 전환 코드가 있다.
실제 구현 범위는 소스/테스트로 확인하고 위 업무 계약 전체의 완료를 추정하지 않는다.
현재 서비스는 loopback 개발 서버이며 직원용 내부망 운영 배포는 추가 작업이다.
개발용 약한 자격증명을 운영에서 재사용하지 않는다. 계정/DB는 GitHub에 포함하지 않는다.
