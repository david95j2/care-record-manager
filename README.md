## DB 자동 승계·업데이트·복원

### 자동 적용

`serve`와 `create-user` 시작 시 동일한 `-DataPath`의 DB 버전을 검사합니다.
현재 v1 데이터를 v2로 올리며, v2 변경은 마이그레이션 이력 테이블과 조회 인덱스 추가뿐입니다.
계정 비밀번호·세션·문서 원본 BLOB·초안·확정 이력·감사 기록은 변경하지 않습니다.
이미 v2이면 다시 적용하거나 불필요한 백업을 만들지 않습니다.
새 DB는 v1→v2를 순서대로 생성합니다. 기존 DB의 버전을 강제로 1로 되돌리지 않습니다.

서버를 정상 종료한 다음, 새 프로그램을 설치하고 같은 데이터 폴더로 실행하세요.
**이 기능은 DB 스키마 승계 기능이지 프로그램 자체의 자동 업데이트 설치기는 아닙니다.**
기존 v1 서버에는 새 잠금 기능이 없으므로 첫 업데이트 전 반드시 기존 서버도 종료하세요.
다른 프로세스를 강제로 종료하지 않습니다.

서버를 시작하지 않고 마이그레이션만 검사·적용하려면:

```powershell
.\run.ps1 -Python 'C:\경로\python.exe' -Migrate -DataPath 'D:\업무데이터\개발검증'
```

1. OS 잠금 및 SQLite 쓰기 잠금을 확보합니다. 잠금을 확보하지 못하면 작업을 중단합니다.
2. 버전뿐 아니라 컬럼·PK·FK·필수 인덱스·무결성·마이그레이션 체크섬을 검사합니다.
3. `데이터폴더/backups/UTC시각-pre-v1-to-v2-고유ID.sqlite3`에 변경 전 백업을 생성하고 검사합니다.
4. 누락된 마이그레이션을 하나의 트랜잭션에서 순서대로 적용합니다.
5. 각 단계 구조·이력 검사가 성공해야 전체를 커밋합니다. 실패하면 전체 롤백 후 원래 버전·구조를 검사합니다.
6. 오류 발생 시 서버를 시작하지 않으며 단계·원래 오류·백업 경로·복구 성공 여부·복구 오류를 출력합니다.

백업은 SQLite backup API를 사용하여 WAL에 남은 커밋 데이터도 포함합니다.
현재 원본 문서는 DB 안에 저장되므로 별도 파일 복사 없이 원본도 백업됩니다.
향후 외부 파일 저장소로 바꿀 때는 파일 백업 계약도 함께 확장해야 합니다.
백업 파일은 성공·실패와 관계없이 자동 삭제하지 않습니다. 민감정보가 포함되어 있으므로 DB와 같은 접근 통제를 적용하세요.

### 명시적 복원

복원은 지정한 백업 시점으로 DB 전체를 되돌립니다. 그 이후의 수정은 복원된 화면에서 사라지므로 주의하세요.
복원 직전 현재 DB도 `backups/*-pre-restore-*.sqlite3`로 보관하므로 다시 되돌릴 수 있습니다.
서버를 정상 종료한 뒤, 백업을 지정하고 명시적으로 승인해야 합니다.

```powershell
.\run.ps1 -Python 'C:\경로\python.exe' -DataPath 'D:\업무데이터\개발검증' `
  -RestoreBackup 'D:\업무데이터\개발검증\backups\실제백업파일.sqlite3' -ConfirmRestore
```

- 현재 실행 중인 새 서버가 있으면 런타임 잠금으로 복원을 차단합니다.
- 복원 대상은 사용자 지정 데이터 폴더의 `development.sqlite3` 하나로 고정됩니다.
- 백업 입력은 읽기 전용으로 검증합니다. 손상·지원하지 않는 버전은 원본을 바꾸기 전에 거부합니다.
- 복원 중 실패하면 복원 직전 백업으로 다시 복구합니다. 이 복구도 실패하면 두 오류와 백업 경로를 모두 보존합니다.
- v1 백업 복원 후 다음 새 서버 시작에서는 v2로 다시 자동 업그레이드합니다.
- 프로그램보다 새로운 버전의 DB는 다운그레이드하지 않고 실행을 차단합니다. 구버전 프로그램을 덮어 설치하지 마세요.

### 보장 범위와 한계

SQLite가 정상 동작하는 환경의 트랜잭션 기반 복구입니다. 디스크 고장·파일 손상·OS/장치가 쓰기 보장을 어기는 상황까지 무손실 복구를 보장하지 않습니다.
트랜잭션 커밋 전 프로세스 종료는 다음 연결 시 SQLite가 복구하며 재실행할 수 있습니다.
백업은 같은 디스크에 있으므로 디스크 장애에 대비한 별도 장치 정기 백업은 여전히 필요합니다.
현재 DB가 이미 손상되어 사전 백업조차 불가능하면 자동으로 덮어쓰지 않고 중단합니다. 원본을 보존한 별도 복구 절차가 필요합니다.
마이그레이션 작성자는 기존 단계를 편집하지 말고 다음 연속 버전을 추가해야 합니다. 단계 안에서 COMMIT·PRAGMA·ATTACH를 실행하지 못하도록 제한합니다.
본체 SQL 트랜잭션 바깥의 파일 이동·다운로드·외부 서비스 호출은 마이그레이션 단계에 넣지 않습니다.

## 화면 테마와 초안 자동저장

- `SIRIUS_BuildDashboard`의 현재 CSS를 읽기 전용으로 참고했습니다. 회색 배경·흰 카드·얇은 경계·검정 주요 버튼·Segoe UI/Malgun Gothic 체계와 상태별 배지를 적용했습니다. 참조 프로젝트의 소스는 변경하지 않았습니다.
- 상단 테마에서 시스템/라이트/다크를 선택합니다. 선택값만 브라우저 localStorage에 저장하고, 시스템 설정은 OS 변경도 따라갑니다. 문서 원본 이미지는 반전하지 않으며 브라우저 내장 PDF 도구의 테마는 브라우저가 결정합니다.
- 입력이 멈춘 뒤 1.2초 후 초안을 서버에 저장합니다. 매출/구간 추가·삭제와 선택값도 대상입니다. 최종 확정은 자동으로 하지 않습니다.
- 저장 중 새 입력은 유지하고 이전 저장 응답으로 덮어쓰지 않습니다. 한 문서의 요청은 순서대로 전송하여 버전 충돌을 줄입니다. 입력 DOM을 다시 만들지 않아 타이핑 커서가 유지됩니다.
- 문서 전환·로그아웃·최종 확정 전에 진행 중 저장을 마칩니다. 저장하지 못하면 이동/확정을 중단합니다.
- 통신 실패·서버 오류는 입력을 화면 메모리에 유지하고 10초 후 재시도합니다. 세션 만료·형식 오류는 사용자 조치가 필요합니다.
- 409 충돌은 자동 덮어쓰기/재시도를 중단합니다. '현재 입력 내보내기'로 JSON을 보관하고 '다시 불러오기'에서 미저장 입력 폐기를 직접 확인합니다. 저장 응답만 유실된 경우에도 보수적으로 충돌을 표시할 수 있습니다.
- 개인정보를 브라우저 저장소에 별도 상시 복제하지 않습니다. 아직 서버에 도착하지 않은 입력은 정전·탭 강제 종료 시 유실될 수 있습니다. '서버 저장 완료' 상태를 확인하세요.
- '현재 입력 내보내기' 파일은 민감한 업무 데이터를 포함할 수 있습니다. 안전한 위치에 보관하세요. 자동 가져오기 기능은 아직 없습니다.

## 사용자 서버 PC 부팅 자동 시작

**현재 개발 PC에는 등록하지 않습니다. 사용자 요청에 따라 등록 스크립트만 준비했습니다.**
`startup-task.ps1`은 Windows Task Scheduler의 부팅 트리거(로그인 트리거 아님)를 사용합니다.
부팅 30초 후 지정한 사용자 계정의 제한된 권한으로 실행하며, 로그인 여부에 의존하지 않는 S4U 방식입니다.
비밀번호를 코드/설정 파일에 저장하지 않습니다. SYSTEM/최고 권한으로 업무 서버를 실행하지 않습니다.

### 등록 전

1. 사용자 서버에 Python 3.11 이상을 일반 설치하고 프로그램을 고정 경로에 배치합니다. WindowsApps/Codex 번들 경로는 업데이트로 바뀔 수 있어 등록에서 거부합니다.
2. 기존 DB가 있다면 **기존 데이터 경로를 그대로 지정**합니다. DB가 없다면 `run.ps1 -CreateUser`로 초기 계정을 먼저 생성합니다.
3. 지정한 실행 계정이 프로그램·Python·데이터·로그 폴더를 읽고 필요한 데이터 파일을 쓸 수 있어야 합니다.
4. S4U는 네트워크 공유/외부 인증 및 EFS 암호화 파일에 접근하지 못하므로 로컬 비-EFS 저장소만 사용합니다. 디스크 전체 암호화와는 다른 제약입니다.
5. Windows 정책에 따라 관리자 PowerShell과 '일괄 작업으로 로그온' 권한이 필요합니다. 등록 실패 시 권한 정책을 우회하지 말고 담당자가 설정해야 합니다.

```powershell
# 설치할 서버 PC에서 실행. 실제 Python/데이터 경로로 바꾸세요.
.\startup-task.ps1 -Action Install -Python 'C:\Python312\python.exe' `
  -DataPath 'D:\활동지원데이터' -Port 8877 -RunAs '서버이름\실행계정'

# 등록 없이 정의만 사전 확인
.\startup-task.ps1 -Action Install -Python 'C:\Python312\python.exe' `
  -DataPath 'D:\활동지원데이터' -WhatIf

# 등록 상태·최근 종료 코드 조회
.\startup-task.ps1 -Action Status

# 운영자가 기동 시험 (중복 서버가 없는지 먼저 확인)
Start-ScheduledTask -TaskName 'ActivitySupportLocalServer'

# 서버를 정상 종료한 뒤 자동 시작 해제. DB·백업은 삭제하지 않음
.\startup-task.ps1 -Action Remove
```

- 등록은 현재 실행 중 프로세스를 강제 종료하거나 새 서버를 즉시 시작하지 않습니다.
- 중복 실행 IgnoreNew, 실행시간 제한 없음, 실패 시 1분 간격 최대 3회 재시도, 배터리 상태로 강제 중단하지 않도록 설정했습니다.
- 작업 이름이 같아도 다른 프로그램의 작업이면 덮어쓰지 않습니다. 실행 중인 작업의 변경·해제도 거부합니다.
- 서버 로그는 `데이터폴더/logs/server.log`에 기록하며 2MB 단위로 순환(이전 로그 최대 5개)합니다.
- 실행 계정이 앱 사용자 계정과 동일한 의미는 아닙니다. 직원은 별도 앱 로그인으로 접속합니다.
- 기존 `.runtime.lock`/마이그레이션을 그대로 사용하므로 자동 시작 때도 데이터 승계·백업 검사가 먼저 실행됩니다.
- 현재 서버는 여전히 `127.0.0.1` 개발용입니다. 부팅 작업 추가가 내부망 포트 개방이나 운영용 웹서버 설치를 의미하지 않습니다.
- 실제 대상 PC의 재부팅 인수 시험은 미수행입니다. 재부팅 후 작업 상태, 로그, 로그인, 기존 문서 조회·자동저장을 확인해야 합니다.

작업 스케줄러 참고: [Microsoft S4U 제약](https://learn.microsoft.com/en-us/windows/win32/taskschd/principal-logontype), [부팅 트리거](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasktrigger).
